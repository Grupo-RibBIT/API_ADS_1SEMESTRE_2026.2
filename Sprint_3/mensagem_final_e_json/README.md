
# 🏡 My Contribution to the Real Estate Telegram Bot

*[Leia em Português](#-minha-contribuição-para-o-telebot-imobiliário)*

In this part of the project, I was responsible for developing what happens after a user finds an apartment they are interested in.

The bot could already search for properties and display results, but it still needed a way for users to **select a property, view its complete information, and save their choices for later**.

My goal was to add these features without changing the existing structure, keeping the search, filters, and navigation working as before.

---

## 🏠 Property Selection

I added the **"Quero esse imóvel!" (I want this property!)** button to the apartments displayed by the bot.

When the user clicks it, the bot identifies the selected property and retrieves its corresponding data.

I also made the selection button disappear after being clicked to prevent repeated interactions with the same message.

This feature works independently from the existing navigation buttons:

- **Acrescentar Filtro** (Add Filter)
- **Mostrar Próximos** (Show Next)
- **Nova Pesquisa** (New Search)

This way, selecting an apartment does not interfere with the search and navigation process.

---

## 📋 Complete Property Details

During a regular search, the bot continues displaying **three properties at a time**, using shorter descriptions.

Once a property is selected, the bot retrieves **all available fields from the corresponding CSV row** and presents the complete information.

The idea was to keep the initial results simple enough to compare different options while providing more details only when the user shows interest in a specific apartment.

All property information comes directly from the CSV file, rather than relying on AI-generated details.

I also added handling for:

- **Empty fields**, preventing invalid information from being displayed.
- **Special characters**, avoiding Telegram HTML formatting issues.
- **Long messages**, respecting Telegram's message length limits.

---

## 👨‍💼 Real Estate Agent Assignment

I integrated the property selection process with the existing `json/corretores.json` file, which contains the registered real estate agents.

Instead of generating random phone numbers, the bot randomly selects an agent from the available records and displays:

- **Name**
- **Phone number**
- **CRECI registration number**

The assigned agent is also saved together with the selected property.

This means that when the user checks the property again, **the same agent's contact information is retrieved**, without performing another random selection.

---

## 🤖 AI-Generated Thank-You Message

After displaying the complete property details and the assigned agent's contact information, I added a thank-you message generated by **Qwen 2.5 Coder 7B**, integrated through **DSPy**.

The AI is only responsible for generating the closing message.

Property and agent information still comes directly from the project's data files, preventing the AI from inventing details.

I also included a fallback message in case the AI fails to generate a response.

### Response Order

1. **Complete property information**
2. **Assigned real estate agent's contact details**
3. **AI-generated thank-you message**

---

## 💾 Selected Properties History

I implemented persistent storage for property selections using `json/apartamentos_escolhidos.json`.

Each selection is associated with the user's **Telegram ID** and stores:

- The selected property's information.
- The assigned real estate agent.
- The date and time of the selection.

Users can save **multiple properties** without losing their previous choices.

I also used `threading.Lock` to control concurrent access during JSON reading and writing operations.

This history is stored separately from the JSON files already used for messages and search filters.

---

## 🔎 Retrieving Saved Properties

I implemented two Telegram commands to retrieve previously saved selections:

| Command | Function |
| --- | --- |
| `/minha_escolha` | Displays the most recently selected property. |
| `/minhas_escolhas` | Displays all properties previously selected by the user. |

I also added support for recognizing certain requests written naturally in the chat.

For example:

- **"Quero ver minha última escolha"** (Show my latest selection)
- **"Quais apartamentos eu escolhi?"** (Which apartments did I select?)
- **"Mostrar minhas escolhas"** (Show my selections)

The recognition also handles variations with and without accents.

These requests retrieve information directly from the saved JSON history, without requiring another property search or assigning a different agent.

---

## 🛠️ Search Filter Fixes

During testing, I found an issue in the `filtrar_csv()` function.

In some searches, the filter interpretation returned a missing value, such as:

```python
Área: [0, None]
```

This could cause a comparison error between `None` and a numeric value, interrupting the search.

I corrected the handling of missing filter limits and adjusted the area filtering logic to prevent incorrect or repeated filtering.

These fixes helped keep the existing search process working properly alongside the new features.

---

## 📁 Files I Worked On

| File | Changes |
| --- | --- |
| `BOTimobiliaria.py` | Property selection button, complete property details, agent contact information, AI-generated thank-you message, history commands, and filtering fixes. |
| `usando_json.py` | Functions to save and retrieve selected properties and assign registered agents. |
| `json/apartamentos_escolhidos.json` | Stores selected properties and their assigned agents. |
| `json/corretores.json` | Existing file used to retrieve registered real estate agents. |

I preserved the project's existing features, including:

- **Displaying three properties per batch**
- **Search filters and result navigation**
- **Geopy**, used for location-related features
- **Whisper**, used for audio message support

The Telegram token and CSV file path remain individual configurations, since each team member runs the bot in their own environment.

---

## ✅ Final Result

With these changes, the interaction no longer ends when the bot displays the search results.

Users can now **select an apartment, receive its complete information, get a real estate agent's contact details, and retrieve their saved selections whenever they need them**.

My contribution focused on developing this property selection and follow-up process, integrating it into the existing code and fixing the filtering issues identified during testing.

# 🏡 Minha contribuição para o Telebot Imobiliário

*[Read in English](#-my-contribution-to-the-real-estate-telegram-bot)*

Nesta parte do projeto, fiquei responsável por desenvolver o que acontece quando o usuário encontra um apartamento de que gosta.

O bot já fazia a pesquisa e mostrava os resultados, mas ainda precisava de uma maneira de **selecionar um imóvel, visualizar seus detalhes completos e guardar essa escolha para consultar depois**.

Meu objetivo foi acrescentar essas funcionalidades sem desmontar a estrutura que já existia, mantendo a busca, os filtros e a navegação funcionando.

---

## 🏠 Seleção do imóvel

Adicionei o botão **"Quero esse imóvel!"** aos apartamentos apresentados pelo bot.

Ao clicar, o usuário seleciona exatamente aquele imóvel, e o código recupera os dados correspondentes à opção escolhida.

Também fiz com que o botão desapareça depois da seleção, evitando novos cliques na mesma mensagem.

Esse processo funciona separadamente dos botões:

- **Acrescentar Filtro**
- **Mostrar Próximos**
- **Nova Pesquisa**

Assim, a seleção do apartamento não interfere no restante da navegação.

---

## 📋 Detalhes completos do apartamento

Na pesquisa normal, o bot continua apresentando **três imóveis por vez**, com descrições mais curtas.

Quando o usuário escolhe um deles, preparei uma resposta com **todos os campos disponíveis na linha correspondente do CSV**.

A ideia foi deixar a primeira apresentação mais simples para comparar opções e reservar os detalhes completos para o imóvel que realmente interessou ao usuário.

Esses dados são retirados diretamente do CSV, sem depender da IA para criar informações sobre o apartamento.

Também incluí cuidados com:

- **Campos vazios**, evitando informações inválidas.
- **Caracteres especiais**, para não prejudicar a formatação.
- **Mensagens muito longas**, respeitando o limite permitido pelo Telegram.

---

## 👨‍💼 Contato de um corretor

Integrei a seleção do imóvel ao arquivo `json/corretores.json`, que já continha os corretores cadastrados.

Em vez de gerar um telefone aleatório, o bot sorteia um dos registros disponíveis e apresenta os dados daquele corretor:

- **Nome**
- **Telefone**
- **CRECI**

O corretor sorteado também é salvo junto com o apartamento escolhido.

Dessa forma, se o usuário consultar a escolha mais tarde, **o contato continua sendo o mesmo**, sem realizar um novo sorteio.

---

## 🤖 Agradecimento gerado pela IA

Depois dos detalhes do imóvel e do contato do corretor, acrescentei uma mensagem de agradecimento gerada pelo **Qwen 2.5 Coder 7B**, integrado ao projeto por meio do **DSPy**.

A IA fica responsável somente por escrever o encerramento.

As informações do imóvel e do corretor continuam vindo dos arquivos do projeto, evitando que a IA invente dados.

Também deixei uma mensagem alternativa caso a geração do texto falhe.

### Ordem da resposta

1. **Informações completas do apartamento**
2. **Contato do corretor selecionado**
3. **Mensagem de agradecimento**

---

## 💾 Histórico dos apartamentos escolhidos

Criei o armazenamento das seleções no arquivo `json/apartamentos_escolhidos.json`.

Cada escolha fica vinculada ao **identificador do usuário no Telegram** e guarda:

- Os dados do imóvel selecionado.
- O corretor atribuído.
- A data e a hora do registro.

O usuário pode selecionar **mais de um apartamento**, sem perder as escolhas anteriores.

Também utilizei `threading.Lock` para controlar o acesso ao arquivo durante as operações de leitura e gravação.

Esse histórico funciona de maneira independente dos JSONs que o projeto já utilizava para mensagens e filtros.

---

## 🔎 Consulta das escolhas pelo Telegram

Implementei dois comandos para recuperar as seleções salvas:

| Comando | Funcionalidade |
| --- | --- |
| `/minha_escolha` | Consulta o apartamento escolhido mais recentemente. |
| `/minhas_escolhas` | Consulta todos os apartamentos já selecionados pelo usuário. |

Além dos comandos, também acrescentei o reconhecimento de algumas solicitações escritas normalmente no chat.

Por exemplo:

- **"Quero ver minha última escolha"**
- **"Quais apartamentos eu escolhi?"**
- **"Mostrar minhas escolhas"**

O reconhecimento também considera variações com e sem acento.

Nessas consultas, o bot utiliza as informações que já foram salvas no JSON, sem exigir uma nova pesquisa e sem sortear outro corretor.

---

## 🛠️ Correções na filtragem

Durante os testes dessa implementação, encontrei um problema na função `filtrar_csv()`.

Em algumas pesquisas, a interpretação dos filtros retornava um valor ausente, como:

```python
Área: [0, None]
```

Isso podia causar um erro ao tentar comparar `None` com um número, interrompendo a pesquisa.

Corrigi o tratamento desses limites ausentes e ajustei a lógica do filtro de área para evitar aplicações incorretas ou repetidas.

Essas correções foram necessárias para manter o fluxo de pesquisa funcionando junto com as novas funcionalidades.
